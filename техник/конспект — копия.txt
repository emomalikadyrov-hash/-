Например, Agile хорош при разработке ПО и сайтов, создании новых продуктов, маркетинговых и рекламных кампаний, творческих проектов. Обосную свой ответ снизу:

3.Самоуправление команд. Работники сами решают, какие задачи взять в работу, в каком порядке и какие инструменты использовать

                     Фреймворк scrum
  Три роли
1. Владелец продукта - (product owner), (список задач)
2. Скрам мастер - (что мешает?), следит за выполняемостью процесса, убирает придяствия.
3. Каманда разработки - (как делать?), сама решает сколько взять задач на интерацию, оптимальный размер (3,4,9)



  Три артефакта
1. Бэклог продукта - (общий список всех задач по продукту), ведет Владелец продукта
2. Бэклог спринта - (содержит в себе задачи, которые команда взяла на текущий спринт, ведет команда)
3. Инкремент - (готовый кусок продукта, которые можно продемонстрировать), результат спринта



Спринт - это короткий отрезок времени((3-4 недели)), за который команда делает готовый кусок продукта.Ритм проекта "Скрам" - это последовательная выполнение спринтом
Ритм проекта скрам (последовательное выполнение спринтов)

царемонии:
1. Планиролвание спринта, проводится в начале спринта, команда выбирает из общегг списка те задачи, которые она сделае за скрипт. Результат - план скрипта.







MVP(разработка минималоьно жизнеспособного продукта)


             Три метода оценки трудоемкости
1.Аналоговый(сравнивание с другими проектами)
2.Параметрический (оценка через формулу)
3.Экспертный (каждый член команды,дает свое оценку(независемо))


mvp - не черновик и не законченная работа, это полность рабочий продукт с минимум рабочими функциями, который полностью решает задачи пользователя

isr - иерархическая структура работы






чек лист - это список конкретных проверяемых утверждении, по которому хаказчики и команда оценивают выполнена ли работа


                     3 категории требованийя:

1. функциональный (что должна делать программа)
2. нефункциональные(как программа должна работать)
3. пользовательский (что должен сделать пользователь)



Чек-лист MVP сайта SchoolHub
1. Функциональные требования
 1. Отображение списка школьных мероприятий.
 2. Просмотр описания каждого мероприятия.
 3. Отображение даты, времени и места проведения.
 4. Возможность регистрации на мероприятие.
 5. Отображение контактных данных организатора.

2. Нефункциональные требования
 1. Простой и понятный интерфейс сайта.
 2. Корректное отображение сайта на компьютере и телефоне.
 3. Быстрая загрузка страниц.
 4. Надёжная работа основных функций.
 5. Защита персональных данных пользователей.

3. Пользовательские требования
 1. Ученик хочет видеть список предстоящих мероприятий, чтобы выбрать подходящее.
 2. Ученик хочет узнать дату, время и место проведения мероприятия.
 3. Ученик хочет зарегистрироваться на мероприятие, чтобы принять в нём участие.
 4. Ученик хочет видеть описание мероприятия, чтобы понимать, что его ждёт.
 5. Ученик хочет иметь возможность связаться с организатором, если у него возникнут вопросы.

Цель MVP: создать минимальную рабочую версию сайта SchoolHub, позволяющую ученикам находить школьные мероприятия и регистрироваться на них
